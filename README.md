# 问卷星自动答题脚本 使用说明（单选 / 多选 / 简答，可自设权值）

> 版本：**v2.3** ｜ 文件：`问卷星单选多选简答（可自己设置权值）.user.js` ｜ 运行环境：Tampermonkey（油猴）
>
> 打开问卷星 vm 版问卷后，自动填写单选、多选、简答三类题目并自动提交，提交成功后自动开始下一份，循环进行；选项和简答答案都可以按权重控制出现比例。

分发或再修改时请保留来源说明；脚本文件头里也写了完整的版权与许可信息。

### 2. 全随机作答的数据有明显问题 ⚠️

**本脚本的答案是“按权重随机”生成的，不是真人作答。** 由此产生的数据有明显特征：

1. **前后自相矛盾**：各题互不关联，会出现逻辑上不可能同时成立的组合；
2. **分布被权重“做”出来**：你配的权重会直接体现在结果分布上，和真实人群未必一致；
3. **跳题 / 关联题对不上**：跳转逻辑、关联题、筛选题会给出互相冲突的组合；
4. **注意力检验题、反向题必露馅**：带“此题请选第二个选项”之类的题，随机作答几乎必错；
5. **答题时长异常**：一份问卷几秒就填完，平台后台能看到每条答卷用时；
6. **来源特征集中**：同一 IP、同一浏览器指纹高频提交；
7. **简答内容是预置句子**，多份之间会重复出现。

**后果**：这类数据基本没有统计分析价值；平台和发布方通常会做答卷清洗（答题时长、IP 去重、逻辑校验），随机答卷很可能被整批判为无效并删除；提交量异常还可能连累整份问卷。

**建议**：要真实数据就请真人填写。本脚本适合自测流程、功能演示、压力测试，最好用自己创建的测试问卷。

## 一、功能概览

| 能力 | 说明 |
|---|---|
| 自动填写 | 单选按权重抽 1 个；多选按权重不放回抽 N 个；简答从答案库里按权重抽 1 条 |
| 自动提交 | 自动点「提交」，并按顺序处理确认弹窗 |
| 循环提交 | 提交成功后自动进入下一份；可设份数上限 |
| 强制跳转自愈 | 提交后被跳到 `completemobile2.aspx` 等完成页会自动计数并跳回问卷 |
| 安全验证 | 阿里云「智能验证」自动尝试点掉；需拖滑块时停手等人工，通过后自动继续 |
| 计数 | 右下角面板显示「已提交 N 份」，同一份只计一次 |
| 控制 | 面板可暂停/继续、立即提交一次 |

适用范围：`https://v.wjx.cn/vm/*.aspx`、`https://www.wjx.cn/vm/*.aspx` 及其提交完成页。旧的 `jq / m / hj` 链接仍走脚本里保留的原版逻辑。

## 二、安装

1. 浏览器安装 **Tampermonkey**（油猴）扩展；
2. 油猴面板 →「添加新脚本」→ 粘贴 `问卷星单选多选简答（可自己设置权值）.user.js` 全部内容 → `Ctrl+S` 保存；
   （也可以把 `.user.js` 文件直接拖进浏览器窗口，油猴会弹出安装页）
3. 确认脚本处于**启用**状态。

脚本的 `@name` 与原版一致，装过旧版的话会直接覆盖，不会出现两个脚本同时提交。

## 三、快速开始

1. 用浏览器打开问卷链接，例如 `https://v.wjx.cn/vm/wUtwYP3.aspx`；
2. 什么都不用点，观察右下角面板：
   - 「正在自动填写答案…」→「正在提交第 1 份…」→「第 1 份提交成功，X 秒后自动进入下一份…」；
   - 「已提交」数字开始递增，说明循环跑起来了；
3. 想停：点面板 **暂停**，或直接关掉标签页。

> **开箱即用但配置是空的**：文件里 `WEIGHTS`（权重）和 `TEXT_ANSWERS`（简答答案）默认都是**注释掉的示例**。也就是说默认状态下：所有选择题等概率、简答题从三条兜底句子（`DEFAULT_TEXT_ANSWERS`）里随机挑。要按自己的问卷来，按第六～八节改。

## 四、支持的题型与填写规则

| 题型 | 页面特征 | 脚本怎么填 |
|---|---|---|
| 单选 | `type=3`，`.ui-radio` | 按权重抽 1 个选项点击；已选过就跳过 |
| 多选 | `type=4`，`.ui-checkbox` | 按权重**不放回**抽 N 个；已选过就跳过 |
| 简答 / 填空 | `type=1/2`，`input` 或 `textarea` | 从该题答案库按权重抽 1 条写入；已有内容不覆盖 |
| 表格题 / 拉条 / 下拉 | `table`、`.slider`、`select` | **不处理**，跳过 |

几个细节：

- 带输入框的选项（如「其他 ____」）会被**自动跳过**，避免触发额外校验；
- 判定题型看的是 DOM 结构，不看 `type` 属性，所以同一问卷里混排也没问题；
- 写入简答时会补 `input/change/keyup` 事件，问卷星的「请输入内容」校验能正常通过；
- 简答题**只填空着的框**，你自己手打的内容不会被覆盖。

## 五、基本参数 CONFIG

在脚本里搜 `var CONFIG = {`（约第 130 行），改数字即可：

```js
var CONFIG = {
    autoStart: true,          // 打开问卷是否立刻开始循环
    intervalMs: 5000,         // 每份成功后等多久进入下一份（毫秒）
    intervalJitterMs: 3000,   // 在上面基础上再加 0~该值 的随机等待
    maxRounds: 0,             // 最多提交多少份，0 = 不限
    submitRetry: 3,           // 每份最多自动点几次「提交」
    clickCooldownMs: 5000,    // 两次自动点击之间的最小间隔
    captchaRetry: 6,          // 安全验证最多自动尝试点几次，之后转人工
    captchaReloadAfter: 2,    // 验证点几次没通过就自动刷新页面重来（0 = 一出现就刷新）
    captchaReloadMax: 3,      // 同一份最多自动刷新几次，防止无限刷新
    multiMin: 1,              // 多选最少勾几项
    multiMax: 0,              // 多选最多勾几项；0 = 上限取“选项数的一半”
    showPanel: true           // 是否显示右下角面板
};
```

| 参数 | 默认 | 常用改法 |
|---|---|---|
| `intervalMs` | 5000 | 想快：`3000`；怕风控：`15000`~`30000` |
| `intervalJitterMs` | 3000 | 配合上面，越大越不规律 |
| `maxRounds` | 0 | 想定量收集就填 `100`、`500` |
| `captchaReloadAfter` | 2 | 验证点不动就刷新重来；设 `0` = 一出现验证就刷新，连点都不点 |
| `captchaReloadMax` | 3 | 同一份最多刷几次；网络/IP 太脏可以调到 `5` |
| `multiMin` / `multiMax` | 1 / 0 | 想固定选 3 项：两个都填 `3` |
| `showPanel` | true | 不想看面板就设 `false`（不影响运行） |

## 六、给选项配权重 WEIGHTS

**位置**：脚本里搜 `var WEIGHTS = {`（约第 165 行）。默认整块是注释状态，按需取消注释并改成你问卷的题号。

### 两种写法

```js
var WEIGHTS = {
    // ① 数组：按选项在页面上的先后顺序给权重
    1: [5, 3, 2, 1],          // 4 个选项 → 概率约 45% / 27% / 18% / 9%

    // ② 对象：按选项文字给权重（写关键词即可，包含匹配、忽略空格）
    2: { '选项1': 6, '选项2': 5, '选项5': 2, '选项6': 0 }
};
```

### 规则

| 规则 | 说明 |
|---|---|
| 默认权重 | 没配的题、没配的选项 = `1`（等概率） |
| 权重 0 | **永不选**该选项（可用来排除「其他」「不知道」这类） |
| 小数 | 支持，如 `2.5`；只影响比例，不影响总量 |
| 数组长度 | 要和该题**选项个数一致**，否则后面的选项会用默认值 1 |
| 多选题 | 按权重不放回抽取，题目要求选几项就抽几项（见第十节） |
| 题目编号 | 就是页面上显示的「1.」「2.」，也是 DOM 里的 `topic` |

### 权重怎么算出来的

权重是相对比例。`[5, 3, 2, 1]` 和 `[50, 30, 20, 10]` 完全等价，总和是 `5+3+2+1=11`，所以第一个选项的概率是 `5/11 ≈ 45%`。

> 💡 **不想自己算？** 跳到[第九节](#九不想自己配权值让-ai-帮你生成)，那里有一段可以直接复制的 AI 提示词，把题目贴给 AI 就能生成整段 `WEIGHTS` 和 `TEXT_ANSWERS`。

## 七、简答题答案库 TEXT_ANSWERS

**位置**：脚本里搜 `var TEXT_ANSWERS = [`（约第 195 行），默认同样是注释状态。

```js
var TEXT_ANSWERS = [
    {
        id: 3,                      // 题号（也支持 qid，或输入框 id，如 'q3'）
        answer: [
            { value: '第一档答案，权重 3，出现概率最高', weight: 3 },
            { value: '第二档答案，权重 2', weight: 2 },
            '不写 weight 就是权重 1'
        ]
    },
    {
        id: 6,
        answer: [
            { value: '答案A', weight: 2 },
            { value: '答案B', weight: 1 }
        ]
    }
];
```

| 要点 | 说明 |
|---|---|
| `id` 写法 | 题号（最常用，如 `3`）、`qid`、输入框 id（如 `'q3'`），能对上一种就行 |
| 答案项 | 字符串（权重 1）或 `{ value, weight }` |
| 权重 0 | 该答案永不使用 |
| 长度限制 | 填空框有 `maxlength` 时会自动截断 |
| 字数要求 | 有些问卷要求最少 5~10 字，答案别写「无」这种过短的 |

**没单独配的简答题**，会从 `DEFAULT_TEXT_ANSWERS` 里随机挑：

```js
var DEFAULT_TEXT_ANSWERS = [
    '暂时没有别的建议。',
    '目前想到的就是这些，谢谢。',
    '暂无补充，问卷设计得比较全面。'
];
```

## 八、完整示例：按 wUtwYP3 配一遍

以 <https://v.wjx.cn/vm/wUtwYP3.aspx>（test问卷，6 道题）为例，它的真实结构是：

| 题号 | 题型 | 选项 / 输入框 |
|---|---|---|
| 1 | 单选 | 4 个：选项1 / 选项2 / 选项5 / 选项6 |
| 2 | 多选 | 6 个：选项1 ~ 选项6 |
| 3 | 简答 | `textarea`（id=q3） |
| 4 | 单选 | 5 个：选项1 / 选项2 / 选项5 / 选项6 / 选项7 |
| 5 | 多选 | 6 个：选项1 ~ 选项6 |
| 6 | 简答 | `textarea`（id=q6） |

对应的配置（把注释去掉即可）：

```js
var WEIGHTS = {
    1: [5, 3, 2, 1],            // 第1题单选，4 个选项
    2: [6, 5, 4, 3, 2, 1],      // 第2题多选，6 个选项
    4: [5, 4, 3, 2, 1],         // 第4题单选，5 个选项
    5: [4, 3, 3, 2, 1, 1]       // 第5题多选，6 个选项
};

var TEXT_ANSWERS = [
    { id: 3, answer: [
        { value: '第3题答案A', weight: 3 },
        { value: '第3题答案B', weight: 2 },
        '第3题答案C'
    ] },
    { id: 6, answer: [
        { value: '第6题答案A', weight: 2 },
        { value: '第6题答案B', weight: 1 }
    ] }
];
```

### 换成别的问卷，怎么找题号和选项

1. 打开问卷页，按 `F12` → 元素（Elements）；
2. 找到题目容器：

   ```html
   <div class='field ui-field-contain' topic='3' id='div3' type='3'>
   ```

   - `topic` = 题号（对应页面上显示的「3.」）
   - `type=3` 单选、`type=4` 多选、`type=1/2` 填空简答
3. 数一下这道题有几个 `.ui-radio` / `.ui-checkbox`，数组权重就写几个；
4. 简答题看输入框的 `id`（如 `q3`）或直接用题号；
5. 保存 → **刷新问卷页** 生效。

## 九、不想自己配权值？让 AI 帮你生成

第六、七节是手动配法。如果题目多、又不想一条条算比例，可以把题目贴给任意 AI（ChatGPT / DeepSeek / Claude / 豆包 / Kimi 都行），让它按题目内容算一套“看起来像正常人”的权重，你复制回脚本就行。

### 怎么用（3 步）

1. **把题目整理出来**：打开问卷页，按题号抄下每道题的题目和选项（`F12` 看 `topic` 最准，也可以直接把题目截图丢给支持图片的 AI）；
2. **复制下面这段提示词**，把【】里的内容换成你自己问卷的信息，连同题目一起发给 AI；
3. **把 AI 输出的两段代码**（`var WEIGHTS = {...}` 和 `var TEXT_ANSWERS = [...]`）**整段替换**脚本里对应的两处，保存 → 刷新问卷页。

> 建议第一次先把 `maxRounds` 设成 `5` 跑几份看看效果（见第五节），确认没问题再改回 `0` 无限循环。

### 拿到结果后怎么核对

| 检查项 | 怎么查 |
|---|---|
| 语法有没有错 | 粘贴保存后油猴没有红色报错、脚本仍是启用状态 |
| 题号对不对 | 和页面上「1.」「2.」的编号一致（DOM 里的 `topic`） |
| 权重个数对不对 | 数一下该题有几个 `.ui-radio` / `.ui-checkbox`，数组就要有几个权重 |
| 分布是不是想要的 | 看 AI 给的第三张表；或先 `maxRounds: 20` 跑一轮，去问卷后台看选项分布 |
| 简答是否自然 | 逐条读一遍，改成你自己的口吻，别一眼看出是模板 |

### 几个小技巧

- 一次最多给 AI **5~10 道题**，题目给太多它容易漏项、对不上号；
- 让它**先给概率表、再给代码**，先看比例是否合理，再决定要不要粘；
- 权重太极端（比如 `[100, 1, 1]`）就直接说「再平均一些」，让它重算；
- 最容易出错的是**数组长度和选项数不一致**，粘之前务必数一遍；
- AI 生成的简答答案可能带书面语或重复，自己顺一遍再粘。

## 十、多选题选几项

按这个顺序决定：

1. **题目写了限制**就按题目来，脚本能识别：
   - 「最多选 3 项」/「限选 3 项」→ 上限 3
   - 「至少选 2 项」/「最少选 2 项」→ 下限 2
   - 「选择 3 项」→ 固定 3 项
2. **没写限制**就用 `CONFIG.multiMin` / `multiMax`：
   - `multiMin:1, multiMax:0`（默认）→ 6 个选项的题，每份**随机勾 1~3 项**；
   - `multiMin:3, multiMax:3` → 固定勾 3 项；
   - `multiMin:2, multiMax:4` → 随机勾 2~4 项。

> 权重为 0 的选项不参与抽取，抽取数量会跟着可用选项数自动收敛。

## 十一、控制面板与状态提示

```
┌──────────────────────────┐
│ 问卷星循环提交            │
│ 第 12 份提交成功，6 秒后   │ ← 状态
│ 自动进入下一份…           │
│ 已提交：12 份             │ ← 计数（本标签页）
│ [ 暂停 ]     [ 立即提交 ] │
└──────────────────────────┘
```

| 面板文字 | 含义 / 处理 |
|---|---|
| 正在自动填写答案… | 正在勾选/填写题目 |
| 正在提交第 N 份（第 K 次尝试） | 正在点提交 |
| 第 N 份提交成功，X 秒后自动进入下一份… | 正常循环中 |
| 第 N 份提交完成，正在跳回问卷继续下一份… | 被跳到完成页，正在跳回 |
| 正在自动通过安全验证… | 正在尝试点掉阿里云验证框 |
| 安全验证没通过，自动刷新页面重试（1/3）… | 验证没点过，正在刷新页面换一次会话 |
| 重复出现上一行 | 一直在「刷新 → 提交」重试，正常 |
| 检测到安全验证：这次要拖滑块，请手动完成… | 需要你拖一下滑块 |
| 安全验证反复失败，请手动完成验证… | 刷新次数用完了，换网络/IP 后点「暂停」再「继续」 |
| 自动点击未生效，请手动点一次页面上的「提交」… | 提交按钮点了没反应 |
| 找不到「提交」按钮，等待页面加载… | 页面未加载完，或不是 vm 版问卷 |
| 已暂停，点「继续」恢复循环 | 你点了暂停 |
| 无法继续提交：已提交过 / 问卷已结束… | 问卷侧限制，脚本已停 |
| 第 N 份提交成功，已达到设定份数，停止循环 | 跑满 `maxRounds` |

> 计数存在 `sessionStorage`，**按标签页独立**：刷新不丢，关标签/换标签从 0 开始。真实份数以问卷后台为准。

## 十二、安全验证怎么处理

提交太快或同 IP 次数太多时，问卷星会弹阿里云「请完成安全验证」：

| 情形 | 脚本行为 | 你要做什么 |
|---|---|---|
| 点一下就变绿（无感验证） | 自动点小方块 → 变绿 → 自动提交 → 继续 | 什么都不用做 |
| 点了没通过（最常见） | **自动刷新页面重来**：刷新后这一份往往能直接提交成功（`captchaReloadMax` 次内） | 什么都不用做，看面板「自动刷新页面重试（1/3）」即可 |
| 点了完全没反应、只接受真人点击（`isTrusted`） | 同上，点 2 次不成就自动刷新（把 `captchaReloadAfter` 设成 `0` 就一出现验证直接刷新） | 不用管；刷新也没用时才需要手动点一下 |
| 升级成拖滑块 / 拼图 | 立刻停手并提示 | 手动拖完，之后自动继续 |
| 刷新次数用完还是失败 | 停止重试并提示 | 换网络/IP 后点「暂停」再「继续」 |

> 这是实测最有效的一招：验证卡住时**刷新一次页面**，下一次提交通常就能直接通过（相当于换了一次验证会话），比一直点验证框有效得多。脚本 v2.3 起已内置。
>
> 网页脚本产生的事件 `isTrusted` 恒为 `false`；若对方 SDK 校验这一项，任何油猴脚本都点不过去——这时靠的就是“刷新重来”或人工点一下。

**减少验证频率**：把 `intervalMs` / `clickCooldownMs` 调大（15~30 秒）、真换出口 IP（手机热点 / 宽带重拨；机房代理反而更容易被判机器）、或换网络时段跑。

## 十三、常见问题

**Q1：改了配置没生效？**
① 确认取消了 `//` 注释；② 油猴里保存后**刷新问卷页**；③ 题号以页面显示的编号为准（不是选项文字里的数字）。

**Q2：权重好像没起作用？**
检查 `topic` 是否等于你写的题号；数组长度是否等于选项个数（例如该题有 5 个选项就写 5 个权重）。可以用面板「立即提交」跑一次，再回问卷后台看分布。

**Q3：面板一直显示「已暂停」？**
点过「暂停」了，点「继续」或刷新页面。

**Q4：多选题一个都没勾上？**
看第十节：题目若要求「至少选 N 项」而你的 `multiMin` 更小，脚本仍会按题目要求选；若选项全被权重 0 排除，脚本会自动退化为等概率，不会空着。

**Q5：简答题没填？**
该题既没在 `TEXT_ANSWERS` 里配，`DEFAULT_TEXT_ANSWERS` 又被清空了；或该题是富文本/特殊控件（脚本只认 `input` / `textarea`）。

**Q6：「已提交」数字和后台对不上？**
面板计数是本地按“识别到的成功次数”估的，且按标签页独立；以后台数据为准。

**Q7：被跳到 `completemobile2.aspx` 卡住了？**
正常，脚本会识别完成页、计数并自动跳回；若停了，刷新该完成页它也会跳回去。

**Q8：多选/简答没填，只填了单选？**
确认脚本是 v2.x（v1.x 只支持单选），并且没有其它同名旧脚本在跑。

**Q9：想只跑固定份数？**
把 `maxRounds` 改成想要的份数，跑满自动停。

**Q10：这些随机答卷能当论文数据吗？**
不能，见开头「使用前必读」。

## 十四、注意事项

- **本项目改自 <https://github.com/ZainCheung/wenjuanxin>（作者 ZainCheung，Apache-2.0），更早来源 [tignioj](https://github.com/tignioj)**；分发或再修改请保留出处；
- **全随机作答的数据有明显问题**（前后矛盾、分布是被权重“做”出来的、答题时长异常、来源集中等），没有统计分析价值，很可能被平台判为无效答卷整批删除；
- 仅用于自动化填写**自己的测试问卷**或**已获授权的问卷**，请勿用于刷量、造假或侵犯他人权益的场景；
- 大量、快速提交可能触发风控（安全验证、限填、问卷被限制），请自行控制频率；
- 修改前建议备份脚本。
